Multi-place questions for the 135M plan model (2026-11-18/19)

Problem: in the browser demo, "regions of Peru that touch the Pacific Ocean" failed with plan-v1-smol135. The model
extracted only "Peru", so the Pacific never became a candidate. gazet-dataset has almost no "filter a set by its
relation to a second named place" questions. Two label bugs made it worse:

1. Container semantics. gazet's templates select "regions of <country>" with ST_Within(region, country). On the
   current Overture data that is false for 31% of regions (1,108 of 3,612, in 137 of 195 countries), and 19% of
   counties against their region: coastal divisions reach past the country's land polygon. So "regions of Peru ..."
   dropped every coastal region, and "regions of Peru that touch the Pacific" returned no rows even with a perfect
   plan. Fix: a country container is the plan's "country" filter (the code is in the candidate row); region
   containers keep "within". 3,528 plan-v1 training targets relabelled (containment, chained, aggregation).
2. Same-name candidates. "Pacific Ocean" is two Natural Earth rows (North and South Pacific) with identical candidate
   rows; rivers are several segments with one name. Labels held one or all of them depending on geography the model
   cannot see (plan-v1: 773 labels left a twin out; first multi-place set: 1,546). v2 learned "pick the first" and
   chose the North Pacific for Peru (no rows again). Fix: a Natural Earth name stands for every candidate row with
   the same name and subtype (expand_twins). Answers are unchanged for per-country questions; "countries on both X
   and Y" answers were recomputed (10 changed).

== Data (gazet_multi.py)

relations: for each of 219 countries, in a memory-capped process: regions and counties (all for countries with <=400
counties, else those of 5 regions), Natural Earth features within 0.6 degrees with distances (0 = intersects),
neighbouring countries (ST_Touches) and containment (ST_Within, gazet's semantics). Canada needed one thread and 2.9 GB.

generate: 10 templates, places in question order, candidates from gazet's own search (gazet.api's per-source limit,
merge and sort), plan targets in canonical order. A question is kept only if the second place matters (the answer
differs from the container alone).
  nat_filter          regions/counties of X that touch/are along/in natural feature Y (sea, river, lake, range, desert...)
  nat_exclude         ... that do not touch Y
  nat_rank            the N largest/smallest ... of X along Y
  nat_union           merge the ... of X along Y
  nat_buffer          ... of X within N km of lake/river Y
  two_nat             ... of X touching both Y and Z
  border_country      regions/counties of X bordering country Z
  border_country_nat  ... bordering Z and touching Y
  seas_both           seas/rivers/lakes/ranges shared by X and its neighbour Z
  countries_both      countries on both sea/range Y and Z
  Questions from 12 countries (CL NG VN PL MX KE NZ TR CO SE MA PH) only go to the test split.
paraphrase: DeepSeek-V4.1-Flash (OpenRouter) rewords each question once. A rewording is kept if every place name is
  verbatim, numbers match, and negation/ranking/merge words agree. Kept 95%, cost $1.08.
variants: short names ("Loja" for "Loja Province", "Lima" for "Province of Lima") with fresh candidates. Kept only if
  every plan ID is still a candidate, the plan is unchanged, and no other division has exactly the short name
  ("Guatemala" for Guatemala Department is dropped). 382 train / 19 test from the new data, 604 single-place and 648
  multi-place (mostly border corridors) from plan-v1. Repeated 3 times in training.
border_country drops "on the X border" / "border with X" phrasings (658), which read like gazet's "border between A
and B" (a buffered shared border).

verify: compiled plans run on the full local data return exactly the expected features in 100 of 100 sampled questions
(10 per template). One known exception outside the sample: ne_1159103969 is two NE rows sharing one ID.

Final set (chatml/gazet_plan_v5 in developmentseed/gazet-generative-sql): 110,863 train records (56,003 plan,
54,860 places), plan-v1's 68,417 records (relabelled) + 17,405 new questions (8,494 paraphrases, 382 short) as plan
and places pairs + short variants. Test: 741 questions (360 paraphrased, 19 short) = eval/multi_test.jsonl.

out of browser memory (a known limit, web/README.md).

== Not covered / next
- Question types the plan language cannot express: distances and nearest ("closest country to X"), directions
  ("regions north of X"), counts and areas, cities and localities (not in gazet's natural-language data).
- Short names are only 19 test questions (v4 79%, v5 74%: 1 question apart); a larger short-name test would settle it.
- intersection (84->72) and adjacency (96->92) on gazet_compat dropped by 3 and 1 questions of 25.
- The same container bug exists in gazet's SQL templates and the old SQL model's data (dataset/scripts/sql_templates.py
  contain_*/chained_*/agg_01-02); not changed there.
- Reproduce: relations -> generate -> paraphrase -> fix-twins -> variants -> variants --multi-only -> export;
  eval with local_eval.sh LABEL GGUF compat, then compat-corrected.
